# draw.io 帮你把工作流程画清楚并保留可修改的图文件

[网站全文](https://aronshare.com/posts/drawio-diagram-editor/)

![draw.io 官方界面](https://aronshare.com/covers/cover_drawio-diagram-editor.webp)


解释一项工作流程时，一长段文字很容易把分支和责任人混在一起。
把步骤画成方框、把判断画成分叉，讨论就能落到具体环节：材料从哪里来，谁负责处理，出错后返回哪一步。
draw.io 适合做这类流程图和关系示意图，官方也提供 diagrams.net 网页入口与独立桌面版。

## 网页入口和桌面版各有用途

[官方编辑器仓库](https://github.com/jgraph/drawio)把 draw.io 定义为绘图与白板应用，并列出了 `app.diagrams.net` 这一在线服务地址。
需要临时打开编辑器，可以从网页入口进入；经常维护本地文件，可以选择桌面版。
[桌面版项目](https://github.com/jgraph/drawio-desktop)基于 Electron 封装同一个核心编辑器，提供 Windows、macOS 和 Linux 版本。

界面左侧是形状库，中间是画布，右侧用于调整图表属性。
矩形、菱形、箭头和文字这些基础元素，已经足够表达许多日常流程。
例如，把“收到申请”“检查材料”“安排处理”分别放进矩形，把“材料是否齐全”放进菱形，用连接线标出通过和补充材料两个方向。
这是一个画图思路，可以换成报销、选题审核或客服处理等自己的场景。

## 图画完以后要保留可修改的文件

流程会变，图也需要跟着改。
编辑器使用 `.drawio` 等图文件保存可编辑内容；把原始文件放进项目资料夹，后续修改节点和说明时就有明确入口。
建议文件名写清对象，例如“客户申请处理流程”，避免长期使用“未命名图表”。

画第一版时，可以只处理一条主流程和一个常见例外。
每个节点写一个具体动作，判断分支标明条件，同一种形状保持相同含义。
如果一张图已经挤满了文字，可以按业务阶段拆开，分别说明输入、处理和结果。
这样的取舍有助于读者理解关系，也方便维护者定位需要修改的环节。

draw.io 的官方说明将它定位为图表工具，SVG 导出主要用于网页嵌入。
需要跨工具继续编辑 SVG 的读者，应按目标软件的要求核对文件兼容性；长期维护流程时，保留 draw.io 原文件更直接。

## 本地使用也要留意外部素材

桌面版官方说明写明，应用不会向外发送图表数据或使用统计，更新检查有独立的开关。
同时，图表可以引用外部图片、背景和字体，打开这样的文件时会请求对应网址。
处理内部资料时，可以采用本地素材，并检查来自陌生来源的图文件是否带有外部引用。

安装包也需要按使用条件选择。
Windows 的安装器、MSI 与便携包有不同的安装方式和权限要求；受公司设备管理限制时，应从[官方发布页](https://github.com/jgraph/drawio-desktop/releases)选择符合管理要求的版本。
普通使用者下载成品安装包即可，源码构建属于另一条使用路径。

## 免费使用与企业部署要分开看

桌面版 README 明确说明可以免费使用，采用 GPL v3 许可。
核心编辑器仓库采用 Apache 2.0，图标、形状库和模板另列了使用条件，其中包含面向 Atlassian 产品及插件生态的限制。
计划二次开发或分发素材时，需要逐项阅读对应条款；自己绘制并导出的图表有单独说明。

官方核心仓库还区分了用于评估的仓库版本和付费生产部署版本，Confluence、Jira 等集成也应单独核对产品条件。
个人想画几张工作流程图，桌面版是明确的免费入口；团队准备搭建内部服务，则需要评估部署、维护和授权范围。

可以用一项正在讨论的工作试画一张图，把主流程、判断条件和负责人说明清楚，并保存可编辑文件。
下次需求变化时，直接在同一份图上修改，比重新解释整段文字更容易保持上下文一致。
