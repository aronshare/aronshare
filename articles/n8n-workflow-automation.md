## 表单到群里那几步一直在靠人搬

客户在网页上填完表单，数据落在表格里。
同事把表格里的行复制到邮件里，发给销售。
销售在群里回一句收到，转头去 CRM 里建一条记录。
这条链路里每个系统都能干活，接口也都在，缺的是把它们串起来的那个东西。
用定时脚本也能串，接口改一次就要改一次代码，token 过期还得手动换。
n8n 就是干这件事的工具，官方文档对工作流的定义很直白，一堆节点连在一起，把某个流程自动化。
一个节点负责取数据，一个节点负责改数据，一个节点负责把结果送进下一个系统。
节点之间的连线决定数据往哪走。
节点之间传的东西叫 item，一行数据就是一个 item，后面的节点按 item 逐个处理。
流程跑起来之后，每一次执行都能点开看，哪个节点收到了什么、发出去什么，一眼能对上线。
出错的那一步会标红，可以把错误交给另一条工作流处理，也可以让它自动重试。

## 画布上的节点和触发器能接上什么

n8n 把集成叫节点，节点是工作流的基本零件。
触发器是其中特殊的一类，官方文档写得很清楚，生产环境的工作流至少要有一个触发器，用来决定什么时候开始跑。
触发器可以是一个定时任务，可以是一个 webhook 地址，也可以是某个应用里发生的事，比如收到邮件、表单提交、代码仓库出现新的 issue。
没有触发器的工作流只能手动点一下执行，调试方便，放到生产就会漏掉该跑的时刻。
官方仓库 README 写的是 1500+ 集成和 9000+ 工作流模板，常见 SaaS 基本都能在节点面板里搜到。
节点面板带搜索，输入应用名或者动作名就能定位，不用一层层翻分类。

![n8n 新建工作流时右侧弹出的触发器选择面板，搜索 issues 后显示 GitHub Issues 节点](https://aronshare.com/assets/post-images/n8n-workflow-automation/detail-2.webp)

模板库里的流程可以直接导进来，改掉凭据和字段就能跑。
凭据单独存在加密的存储里，节点里只引用名称，换账号不用动流程本身。
一条工作流也能当成节点嵌进另一条，长流程拆成小块更好维护。
除了应用节点，还有一批核心节点负责流程本身。
条件判断把数据分成两条路，合并节点把两路合回来，循环节点处理列表，等待节点可以停在那儿等人工审批。
代码节点能写 JavaScript，也能切到 Python，把节点面板拼不出来的逻辑塞进去。
自托管时可以在代码节点里引入 npm 包，云版本不开放外部模块，只给 crypto 和 moment 两个。
AI 用的是同一套画布逻辑，AI Agent 节点下面挂着几个子接口，聊天模型、记忆、工具、输出解析器各连一个节点。
模型可以接 OpenAI、Anthropic、Google，也可以接 Ollama 这类本地跑的模型。
向量库节点覆盖 PGVector、Qdrant、Pinecone、Milvus、Weaviate、Redis 这些常见后端，配上嵌入节点和文档加载器就能做检索。
官方另外提供 MCP 的入口，Agent 在节点面板里就能连上 MCP 服务器。
AI 流程可以挂评估，拿一批样例跑打分，改完提示词能看出好坏。
