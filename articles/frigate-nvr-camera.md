# Frigate 让家用摄像头在本地认出人和车

BODY

摄像头装在家里或者店门口，录像是 24 小时不停地写进硬盘。
真出事要回看的时候，一大段没有事件标记的视频得靠人眼快进。
Frigate 把这件事换个做法，让录像机自己判断画面里有没有值得留意的东西。

它是开源的网络录像机，代码在 GitHub 上公开，用 MIT 许可。
运行的时候调用 OpenCV 和 TensorFlow，在本机对 IP 摄像头做实时目标检测，视频和识别结果都不出内网。
官方明确写了，想让识别跑得动，最好配一块 GPU 或者 AI 加速卡，加速卡的开销比纯 CPU 低很多。

省资源的设计是它和普通录像机最大的区别。
它先用开销很低的运动检测判断画面哪里动了，只在动过的区域跑目标检测，没动静的时候几乎不占算力。
检测进程单独跑，优先保证实时出结果，每帧都硬算一遍会把速度拖下来。

![Frigate 手机端实时监控页，两个摄像头画面叠着时间戳](https://aronshare.com/assets/post-images/frigate-nvr-camera/detail-1.webp)

*官方文档截图，手机界面把后院和门口两路画面竖直排列。*

事件列表是日常用得到的那一页。
每条事件的缩略图、摄像头、识别对象、置信度分数、区域和起止时间排在一起，翻起来比逐个视频拖进度条快得多。
录像按检测到的对象设置保留期，也可以开 24 小时不间断录制，两种策略能同时存在。

![Frigate 事件列表，按摄像头和识别对象筛选](https://aronshare.com/assets/post-images/frigate-nvr-camera/detail-2.webp)

*官方文档截图，表格里是 person 事件的分数、区域和起止时间。*

对外接口给得比较顺手。
检测结果通过 MQTT 发出去，Home Assistant 有专门的集成组件，灯、门铃、通知都能挂上去。
摄像头连接数多的时候可以走 RTSP 转发，由 Frigate 统一拉一路再分给客户端，实时预览用 WebRTC 和 MSE，延迟比 HLS 低。

部署走 Docker，配置文件是一份 YAML。
摄像头地址、检测区域、要识别的对象、录像保留策略都写在里面，改完重启容器生效。
价格上没有订阅，软件本身免费，成本落在摄像头、硬盘和那块加速硬件上。
商标属于 Frigate, Inc.，代码许可是 MIT，二次分发要保留版权声明。

家里三四路摄像头，一台带核显的小主机就能跑起来；要上到十几路并且开高分辨率检测，加速卡的钱省不掉。
摄像头接进来、跑通一路检测之后再决定要不要加硬件，比一上来堆配置省事。
